## 1. ENVIRONMENT SETUP

### Requirements
- **PHP:** 8.4+ (required by Laravel 13). Verify with `php -v` before proceeding.
- **Composer:** Latest stable 2.x. All PHP dependencies via Composer only.
- **Node.js & NPM:** LTS — required for Vite asset compilation via the project's frontend starter.

### Bootstrap Sequence (in order)
1. Create the project with the appropriate starter (the starter, NOT Boost, provides the frontend stack — Vite, Tailwind CSS, TypeScript):
   `composer create-project laravel/laravel:^13.0 <project-name>`
   (If a specific stack is required — Livewire, Inertia + React/Vue/Svelte — use the corresponding official starter instead.)
2. `cp .env.example .env` then `php artisan key:generate`
3. Configure `.env` for local development:
   - `APP_ENV=local`, `APP_DEBUG=true`, `APP_URL=http://localhost`
   - Database: `DB_CONNECTION=mysql` (or per requirements)
   - Queue/Cache/Session: `QUEUE_CONNECTION=redis`, `CACHE_STORE=redis`, `SESSION_DRIVER=redis` — never `sync` outside local dev
   - Mail: `MAIL_MAILER=log`
4. `composer install && npm install`
5. Verify `npm run dev` compiles assets with HMR before continuing.

## 2. LARAVEL BOOST (INSTALL EXACTLY PER OFFICIAL DOCUMENTATION) ⚠️

Boost is a **dev-only AI-assistance package** — it is NOT a frontend build tool and provides NO Vite/Tailwind functionality. Do not conflate it with the asset pipeline.

### Installation (verbatim from laravel.com/docs/boost)
1. `composer require laravel/boost --dev`
2. `php artisan boost:install`
   - This is an **interactive installer** that auto-detects installed IDEs/agents (Cursor, Claude Code, etc.). When running non-interactively, accept the recommended defaults: MCP server ✅, AI guidelines ✅, agent skills ✅, project rules ✅.
   - The command generates agent guideline files (e.g., `CLAUDE.md`, `AGENTS.md`), the MCP config (`.mcp.json`), the `boost.json` config, and package-specific skills based on what it detects in `composer.json` ().

### Post-installation configuration
- **`.gitignore`:** Add `.mcp.json`, `boost.json`, and generated guideline files (`CLAUDE.md`, `AGENTS.md`, etc.) — these are auto-regenerated by `boost:install` / `boost:update`. **Commit `.ai/rules/` to version control** — project rules are shared team knowledge ().
- **Keeping Boost updated:** Add to `composer.json` scripts so Boost resources refresh on every dependency update:
  ```json
  "scripts": {
      "post-update-cmd": ["@php artisan boost:update --ansi"]
  }
  ```
  Use `php artisan boost:update --discover` after adding new ecosystem packages so their guidelines/skills get published ().

### How you MUST use Boost during development
- **MCP tools:** When the Boost MCP server is available, use its tools instead of guessing — `database-schema`, `database-query`, `list-routes`, `last-error`, `read-log-entries`, `application-info` — to inspect the *actual* state of the app before and after changes ().
- **Search Docs:** Before using any Laravel ecosystem API you are not 100% certain about, query the Boost documentation API (17,000+ version-specific entries) rather than relying on memory.
- **Project rules:** When you establish a convention (e.g., "all money is integer cents"), record it via the `record-rule` MCP tool or by asking to "remember" it — never create rule files by hand, as Boost regenerates `.ai/rules/index.md` ().
- **Custom guidelines/skills:** Add team-specific guidance as `.ai/guidelines/*.md` files; add domain skills (e.g., `.ai/skills/creating-invoices/SKILL.md`) with YAML frontmatter (`name`, `description`).
- **Conventions inference:** For an existing codebase, run the `infer-conventions` skill (present each discovered convention for approval before recording) instead of inventing rules from scratch ().

## 3. PROJECT ARCHITECTURE & CODING STANDARDS

### Coding Standard
- **PSR-12** baseline, enforced by **Laravel Pint** — run `vendor/bin/pint` after every code-writing operation. No generated code may fail Pint.

### Directory & Naming Conventions
- Follow Laravel 13's default structure. No custom abstraction layers (e.g., no `app/Repositories`) unless explicitly required.
- **Actions** for single-responsibility business logic: `app/Actions/<Domain>/<ActionName>.php`
- **Form Requests** for ALL controller validation — never validate in controllers.
- **API Resources** for ALL API responses — never return raw models.
- **Enums** for fixed value sets; **DTOs** for complex data passed between services.
- **Policies** for authorization, registered in `AppServiceProvider::boot()`.
- **Events/Listeners** for side effects; **Jobs** for slow/external/retryable work.
- Naming: singular StudlyCase models (`Order`), plural snake_case tables (`orders`), camelCase relationships, snake_case columns/variables.

### Laravel Idioms
- Thin controllers (1–3 calls); business logic in Actions/Services or model methods — never duplicated.
- Constructor-inject via the container; never `new` framework services.
- Reach for Laravel built-ins first: Collections, pipelines, `when()`, query builder before raw SQL.

## 6. DATABASE & MIGRATIONS

1. Verify connectivity via the Boost MCP `database-connections` / `database-schema` tools before writing migrations.
2. Discipline:
   - One migration per schema change; never edit a migration already run outside the local machine.
   - Descriptive verb names: `create_orders_table`, `add_status_to_orders_table`.
   - Every table: `id()`, `timestamps()`; relations via `foreignId()->constrained()->cascadeOnDelete()`.
   - Indexes on every FK and every column used in `where()`.
   - Correct types: `decimal(10,2)` for money, `json` for flexible payloads.
3. `DatabaseSeeder` orchestrates domain seeders; every model has a factory; a factory-seeded admin user exists locally.

## 7. DEVELOPMENT WORKFLOW

### New Model
1. `php artisan make:model <Name> --all`
2. Fill migration → `php artisan migrate:fresh --seed`
3. `$fillable`, casts, relationships, scopes on the model; create + register Policy.
4. Pest feature tests for the full CRUD cycle.

### New Controller
1. `php artisan make:controller <Name>Controller --api`
2. Validation via `make:request Store<Name>Request`; delegate to an Action; return API Resources.

### New Action / Service
1. Single public method (`execute()`/`handle()`), constructor-injected dependencies.
2. Wrap side effects in `DB::transaction()`.

### Every code change must
- Pass `composer fix && composer analyse && composer test`.
- Be covered by Pest tests you wrote or updated.
- Follow patterns detected in the codebase (§8) and recorded Boost project rules.
- Record any newly established convention via `record-rule`.
